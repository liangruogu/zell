# Zell 通信架构文档

本文档完整描述了 Zell 项目的所有 WebSocket 连接、HTTP 请求和实时广播逻辑。

## 二、协作项目完整生命周期

### 2.1 阶段一：创建项目 & 开启协作（Owner 端）

```
Owner 在 HomePage 创建项目
  → Tauri invoke('create_project', ...)
  → 本地 SQLite 存储

Owner 进入 ProjectPage
  → Tauri invoke('get_project', { id })
  → 显示项目信息
  → 输入服务器地址 + 密钥，点击"连接"
  
  → GET /health                     (健康检查)
  → POST /api/v1/projects/:pid/collab  (开启协作)
      Body: { enabled: true, owner_token: <UUID>, name: <项目名> }
      服务器: 创建项目记录、生成 JWT token、创建邀请码
  ← Response: { token: <JWT>, invite_code: "BNDL-..." }
  
  → 保存 token + invite_code 到项目 settings
  → Tauri invoke('update_project', ...)
```

### 2.2 阶段二：成员加入

#### 入口 A：HomePage 加入

```
成员在 HomePage 点击"加入项目"
  → 输入服务器地址 + 邀请码 + 显示名称
  → POST /api/v1/projects/join
      Body: { code: "BNDL-xxx", client_id: <UUID>, display_name: "张三" }
      服务器: 验证邀请码、创建 session、返回 token
  
  ← Response: {
      status: "approved",
      project_id: <UUID>,
      project_name: "项目名",
      token: <JWT>,
      display_name: "张三"
    }

  → Tauri invoke('create_project', { id: project_id, name: project_name, settings: {serverUrl, token, ...} })
  → GET /api/v1/projects/:pid/articles    (同步所有文章)
  → 导航到项目
```

#### 入口 B：InviteDialog（项目内部加入）

```
已进入项目的用户通过 InviteDialog 输入邀请码加入
  → POST /api/v1/projects/:pid/join
      Body: { code: "BNDL-xxx", client_id: <UUID>, display_name: "李四" }
  ← Response: { status: "approved", token: <JWT>, ... }
  
  → 更新本地项目 settings（添加 token）
  → Tauri invoke('update_project', ...)
```

**服务器 join 流程：**
```
POST /join
  → 解析 code 获取 project_id
  → 验证邀请码是否匹配
  → 查找或创建 member 记录
  → 生成 JWT token (sub=client_id)
  → hub.BroadcastProject(pid, "member_joined", {client_id, display_name})
  → 返回 token
```

### 2.3 阶段三：进入项目后的数据同步

#### ProjectPage（项目概览页）

```
进入 ProjectPage
  → Tauri invoke('get_project', { id })     (本地数据)
  → 启动 setInterval(fetchCollabData, 5000)  (每5秒轮询)

fetchCollabData() 每次轮询:
  → GET /health
  → GET /api/v1/projects/:pid/members      (成员列表，仅 owner)
  → GET /api/v1/projects/:pid/invite-code   (邀请码，仅 owner)
  → GET /api/v1/projects/:pid/info          (项目信息，有 token 的成员)
      如果服务器 name/desc 与本地不同:
        → Tauri invoke('update_project', ...)  同步到本地 DB
```

**注意：ProjectPage 没有 WebSocket 连接。** 它完全依赖 HTTP 轮询。

#### KnowledgeBasePage（知识库页）

```
进入 KnowledgeBasePage
  → Tauri invoke('get_project', { id })     (本地数据)
  → Tauri invoke('get_knowledge_articles')  (本地文章)
  
  → GET /api/v1/projects/:pid/info           (同步项目信息，新增！)
  → GET /api/v1/projects/:pid/articles       (同步所有文章)

  → 建立 WebSocket 连接到通知频道
      ws://server/ws/:pid/__notifications__?token=<JWT>

  → WebSocket onopen:
      → syncArticlesFromServer()            (再次同步文章)
      → GET /api/v1/projects/:pid/notifications (拉取离线通知)
```

## 三、WebSocket 详细说明

### 3.1 连接端点

**唯一端点：** `GET /ws/:pid/:aid`

两个频道类型由 `:aid` 路径参数区分：

| 频道类型 | URL 示例 | 用途 | 消息格式 |
|---------|---------|------|---------|
| **通知频道** | `/ws/abc123/__notifications__` | 接收项目级事件广播 | JSON 文本 |
| **协作编辑频道** | `/ws/abc123/article-uuid` | Yjs CRDT 实时协同编辑 | 二进制 (protobuf) |

### 3.2 服务器端频道注册

**文件：** `server/internal/handler/ws_handler.go`

```
1. 客户端连接 ws://server/ws/{pid}/{aid}
2. 服务器构造 room key: pid + ":" + aid
   例如: "abc123:__notifications__" 或 "abc123:article-uuid"

3. 解析 token 获取 clientID (JWT 的 sub 字段)

4. 如果不是通知频道 (aid !== "__notifications__"):
   → 检查项目状态 (deleted? collab_enabled?)
   → 检查成员状态 (active?)
   → 不通过则返回 403

5. 如果是通知频道 (aid === "__notifications__"):
   → 跳过所有状态检查 (仅验证 token)
   → 直接升级为 WebSocket

6. 客户端注册到 Hub 的对应 room
   → hub.onMemberEvent → 广播 member_online
```

### 3.3 Hub 广播机制

**文件：** `server/internal/ws/hub.go`

```
BroadcastProject(projectID, event, data):
  1. 构造 JSON: { type: event, project_id: projectID, data: data }
  2. 遍历所有 room
  3. 只发送给 key 以 "projectID:__notifications__" 开头的房间
  4. 不发送到 Yjs 协作房间

broadcast(room, sender, msg):        (小写，私有的)
  1. 查找指定 room 的所有客户端
  2. 排除发送者自身
  3. 转发 Yjs 二进制消息
  4. 如果是 Update 类型，触发快照保存
```

### 3.4 通知频道客户端处理

**文件：** `app/src/pages/KnowledgeBasePage.tsx`

```
connect():
  → 从 store 读取 serverUrl + token
  → 创建 WebSocket: ws://server/ws/:pid/__notifications__?token=<JWT>
  → 仅在 projectId 变化时重新建立连接
  → 断开时自动重连 (3秒后)

onopen:
  → setServerOnline(true)
  → syncArticlesFromServer()        // 同步文章
  → pullNotifications()              // 拉取离线通知

onmessage:
  收到消息后根据 msg.type 处理:
  
  ┌─────────────────────┬────────────────────────────────────┐
  │ msg.type            │ 客户端处理                          │
  ├─────────────────────┼────────────────────────────────────┤
  │ project_deleted     │ 弹窗 → 删除本地项目 → 跳转首页      │
  │ collab_disabled     │ 弹窗 → 删除本地项目 → 跳转首页      │
  │ member_removed      │ 弹窗 → 删除本地项目 → 跳转首页      │
  │ article_*           │ 触发 syncArticlesFromServer()      │
  │                     │ (当前编辑的文章跳过)                │
  │ project_updated     │ 更新 store 中的 project.name/desc   │
  │ member_joined/left  │ (不处理，由 ProjectPage 轮询获取)   │
  │ member_online/offline│ (不处理，由 ProjectPage 轮询获取)  │
  └─────────────────────┴────────────────────────────────────┘

onclose:
  → setServerOnline(false)
  → setReadOnly(true)
  → 3秒后自动重连
```

### 3.5 协作编辑频道客户端处理

**文件：** `app/src/components/editor/MarkdownEditor.tsx` (line 140)
**文件：** `app/src/hooks/useCollaboration.ts` (line 23)

```
使用 y-websocket 库 (WebsocketProvider):
  url: ws://server/ws/:pid/:articleId?token=<JWT>
  
  → 自动处理 Yjs CRDT 同步
  → awareness 协议用于光标同步
  → 连接/断开时设置本地 awareness state
```

## 五、全部 WebSocket 广播事件

所有广播事件通过 `Hub.BroadcastProject()` 发送，消息格式：

```json
{
  "type": "<事件类型>",
  "project_id": "<项目ID>",
  "data": { ... }
}
```

| # | 事件类型 | 触发场景 | data 内容 | 源文件 |
|---|---------|---------|----------|--------|
| 1 | `member_online` | 客户端连接 WebSocket | `{client_id}` | `ws_handler.go:35` |
| 2 | `member_offline` | 客户端断开 WebSocket | `{client_id}` | `ws_handler.go:38` |
| 3 | `article_created` | 新建文章 (POST/PUT) | 完整 Article 对象 | `article_handler.go:70,103` |
| 4 | `article_updated` | 更新文章 (PUT) | 完整 Article 对象 | `article_handler.go:116` |
| 5 | `article_deleted` | 删除文章 (DELETE) | `{id: "<aid>"}` | `article_handler.go:127` |
| 6 | `project_deleted` | Owner 删除协作项目 | `{project_id}` | `invite_handler.go:54` |
| 7 | `collab_disabled` | Owner 关闭协作 | `{project_id}` | `invite_handler.go:64` |
| 8 | `project_updated` | Owner 更新项目信息 | `{name, description}` | `invite_handler.go:121` |
| 9 | `member_joined` | 新成员通过邀请码加入 | `{client_id, display_name}` | `invite_handler.go:244` |
| 10 | `member_removed` | Owner 移出成员 | `{client_id}` | `invite_handler.go:277` |
| 11 | `member_left` | 成员主动退出 | `{client_id}` | `invite_handler.go:291` |

## 七、关键数据流详解

### 7.1 Owner 更新项目信息 → 成员收到更新

```
Owner 在 ProjectPage 编辑项目 → 点击保存
  │
  ├─→ Tauri invoke('update_project', ...)     (更新本地 DB)
  │
  └─→ PUT /api/v1/projects/:pid/info          (同步到服务器)
        Headers: X-Server-Key: <key>
        Body: { name: "新名称", description: "新描述" }
        │
        ▼
      服务器 UpdateProjectInfo()
        ├─→ db.UpdateProjectInfo(pid, name, desc)
        └─→ hub.BroadcastProject(pid, "project_updated", {name, desc})
              │
              ▼
            遍历所有 room，只发送到 "pid:__notifications__" 频道
              │
              ├─→ 成员 A 在 KnowledgeBasePage → 收到 WebSocket 消息
              │     → setCurrentProject({...proj, name, description})
              │
              └─→ 成员 B 在 ProjectPage → 没有 WebSocket!
                    → 只能等下次轮询 (5秒后) GET /info
                    → 对比发现不同 → updateProject() 更新本地
```

### 7.2 Owner 创建文章 → 成员收到新文章

```
Owner 在 KnowledgeBasePage 创建文章
  │
  ├─→ Tauri invoke('create_knowledge_article', ...)  (创建本地)
  │
  └─→ POST /api/v1/projects/:pid/articles
        Headers: Authorization: Bearer <JWT>
        Body: { id, project_id, title, content, ... }
        │
        ▼
      服务器 ArticleHandler.Create()
        ├─→ db.CreateArticle(...)
        └─→ hub.BroadcastProject(pid, "article_created", article)
              │
              ▼
            通知频道中的成员收到 "article_created"
              → KnowledgeBasePage: syncArticlesFromServer()
              → 拉取全部文章列表
              → 对比本地，新增/更新/删除
```

### 7.3 Yjs 实时协同编辑

```
用户 A 编辑文章 (在同一文章页面)
  │
  └─→ y-websocket 连接: ws://server/ws/:pid/:articleId?token=...
        │
        ▼
      服务器 Hub.HandleWebSocket()
        → 注册到 room "pid:articleId"
        │
        ▼
      用户 B 也在编辑同一文章
        → 也注册到同一 room "pid:articleId"
        │
        ▼
      用户 A 输入文字
        → Yjs 生成 CRDT 更新
        → y-websocket 通过 WebSocket 发送二进制消息
        │
        ▼
      服务器 ReadLoop() 收到消息
        → hub.broadcast(room, sender, msg)
        → 转发给 room 中除 sender 外的所有客户端
        │
        ▼
      用户 B 的 y-websocket 收到消息
        → Yjs 应用更新到文档
        → 编辑器实时显示更改
        → 同时触发 onSnapshot → 保存到服务器 DB
```

### 7.4 客户端进入项目时的数据加载顺序

```
KnowledgeBasePage 挂载
  │
  ├─ [Effect 1] Tauri invoke('get_project', { id })
  │              Tauri invoke('get_knowledge_articles', { projectId })
  │              → 从本地 SQLite 加载数据
  │
  └─ [Effect 2] (仅依赖 projectId)
       │
       ├─ trySetup(): 读取 store 中的 settings
       │    ├─ serverUrl 为空? → 等待 (subscribe 监听 store 变化)
       │    └─ serverUrl 存在? → 立即执行以下:
       │
       ├─ syncProjectInfoFromServer()
       │    → GET /api/v1/projects/:pid/info
       │    → 对比 name/desc，不同则 updateProject() 保存到本地
       │
       ├─ syncArticlesFromServer()
       │    → GET /api/v1/projects/:pid/articles
       │    → 对比本地文章，创建/更新/删除
       │
       └─ connect()
            → WebSocket ws://server/ws/:pid/__notifications__?token=...
            → onopen:
                → syncArticlesFromServer() (再同步一次，防止遗漏)
                → pullNotifications() (拉取离线通知)
            → onmessage: 处理各事件 (project_updated, article_* 等)
            → onclose: 3秒后自动重连
```
